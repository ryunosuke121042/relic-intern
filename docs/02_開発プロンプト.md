# 開発プロンプト（最終版）

このプロンプトでアプリ（`app/` の完全版）を作りました。

```markdown
次のWebアプリのプロトタイプを作ってください。
スマホで開かれることを最優先にしてください。

# プロダクト
- 名前：目標達成アプリ
- 一言で：勉強計画が崩れたとき、遅れた分の組み直しをAIが代わりにやり、スマホの画面に新しい予定を届けるアプリ
- 対象ユーザー：毎日30分などの勉強計画を立てても、急な課題や用事で崩れ、遅れを組み込み直すのが面倒で1〜2週間でやめてしまう大学生
- 検証したいこと：組み込み作業がなくなれば、モチベーションが下がっていても翌日また30分に戻れるか。まずは自分で使い、2日以上予定どおりにできなかったときに、1週間以内に3回以上連続で計画どおりにできたかを記録して確かめる

# 作る範囲
- 作るもの：聞き取り、AIとの共同計画作成、日々の記録、崩れたときの自動組み直し、Web Pushでの遅れ・予定の通知、検証記録
- 作らないもの：原因・行動傾向の分析、復習・休息・バッファーの考慮、使うほどの個人最適化、印刷用プランナー、ウィジェット、統計グラフ、SNSシェア
- ログイン画面は作らない。Supabaseの匿名認証で端末ごとにユーザーを作り、リロードしても翌日開いてもデータが消えないようにする
- AIの呼び出しと通知の送信はサーバー側（Supabase Edge Functions）で行う。APIキーをブラウザに出さない

# 技術スタック
- Vite + React + TypeScript
- Tailwind CSS
- shadcn/ui（Button、Card、Input、Dialog、Toastをsrc/components/uiに置く）
- lucide-react（アイコン）
- react-router-dom（画面遷移）
- date-fns（日付処理。タイムゾーンはAsia/Tokyo）
- vite-plugin-pwa（PWA化とService Worker）
- Supabase（データベース、匿名認証、Edge Functions、pg_cronによる定期実行）
- web-push（Edge FunctionsからのWeb Push送信。VAPIDキーを使う）

# データ設計
- 型はsrc/types.tsに定義する
- Plan：id(uuid), user_id, goal(例：経済学の期末試験), deadline('YYYY-MM-DD'), daily_minutes(15 | 30 | 60), available_weekdays(number[]), time_slot(string), busy_note(string), created_at
- Task：id(uuid), plan_id, date('YYYY-MM-DD'), title(例：第3章 需要と供給), minutes, status('pending' | 'done' | 'missed'), original_date('YYYY-MM-DD' | null、組み直しで移動したときの元の日), updated_at
- Replan：id(uuid), plan_id, triggered_at, missed_task_ids(uuid[]), proposal(組み直し後の今後7日のTask案、JSON), confirmed_at(ISO文字列 | null)
- PushSubscription：id(uuid), user_id, endpoint, p256dh, auth, created_at
- 予定日を過ぎても記録がないTaskは、その日の終わりに'missed'にする
- 「崩れた」は、予定のある日が2日連続で'missed'になったときとする
- 「戻れた」は、組み直しを確定してから7日以内に、予定のある日で3回連続'done'になったときとする
- 保存と読み込みはsrc/lib/repository.tsに集約し、画面からSupabaseを直接触らない
- repositoryは getActivePlan / savePlan / listTasks(from, to) / setTaskStatus / getLatestReplan / confirmReplan / listReplanLogs をPromiseを返す非同期関数として公開する

# 画面
## 1. / 今日（ダッシュボード）
- 今日の日付と、今日の勉強タスク（例：経済学 30分「第3章 需要と供給」）を大きく表示
- 「できた！」と「今日はムリ」の2ボタン。ワンタップで記録する
- 「今日はムリ」を押したら責めず「明日の予定はこちらで考えておきます」とだけ返す
- 直近7日分の達成状況を小さく並べる（できた／ムリ／未記録）
- 2日以上「ムリ」または未記録が続いたら、画面上部に組み直し後の予定をカードで表示し、タップで /replan へ移る
- 計画が0件のときは「まずは目標を教えてください」と /onboarding へのボタンを出す

## 2. /onboarding 聞き取り
- 1画面1問で、タップ中心に答えられる形にする
- 聞くこと：目標（例：経済学の期末試験）、期限（日付）、1日に使える時間（15分／30分／60分）、勉強できる曜日と時間帯、決まっている忙しい予定（バイト、サークルなど）
- 最後にAIが足りない点を1〜2問だけ追加で聞く
- 答え終わったら /plan へ移る

## 3. /plan 一緒に計画を作る
- AIが期限までの日別タスク案を作り、日付ごとのリストで表示する
- 各日をタップすると「この日はムリ」「量を減らす」「別の内容にする」を選べる。選ぶとAIがその部分だけ作り直す
- 自由入力欄で「土曜は全部休みにしたい」のように頼むこともできる
- 「この計画で始める」で確定し、/ へ戻る

## 4. /replan 組み直し案
- 遅れた分（どのタスクが何日分か）と、組み直し後の今後7日の予定を並べて表示する
- 変わった日には印をつけ、どこに何が入ったかひと目でわかるようにする
- 「この予定でいく」をワンタップで確定できる
- 直したい場合は /plan と同じ「この日はムリ」「量を減らす」で部分修正できる
- 開いてから確定まで8タップ以内・1分以内で終わる構成にする

## 5. 通知とホーム画面
- PWAにして、初回の計画確定後に「ホーム画面に追加」と通知許可を案内する
- 2日連続で「ムリ」または未記録になった日の夜に、Web Pushで遅れを通知する（例：「経済学、2日分の遅れがあります」）
- その翌日以降は、通知に組み直し後の今日の予定そのものを表示する（例：「今日：経済学 30分（第3章の続き）」）
- 通知をタップすると /replan が開く

## 6. /log 検証記録
- 「2日以上崩れた日」「組み直しを確定した日」「その後1週間以内に3回連続でできたか」を一覧で表示する
- 3回連続でできたら「戻れた」と表示する

# AI（Edge Functions）
- generate-plan：聞き取りの答えから、期限までの日別Task案をJSONで返す
- adjust-plan：指定された日について「この日はムリ」「量を減らす」「別の内容にする」または自由入力の依頼を受け、その部分だけ作り直したTask案を返す
- replan：崩れたときに遅れたTaskを組み直す
  - 遅れたTaskを、期限までの予定可能な曜日の空いている日に振り分ける
  - busy_noteにある忙しい日には入れない
  - 1日の合計がdaily_minutesを超えない。収まらない場合は内容を減らす案を出す
- AIの出力は必ずJSONで受け取り、形が崩れていたら1回だけ再試行する。それでも失敗したら、遅れたTaskを後ろの空いている日に順番に詰める単純なルールで組み直す

# AIの組み直しルール
- 2日以上「ムリ」または未記録が続いたら自動で組み直す
- 遅れたタスクを期限までの空いている日に振り分ける。忙しい予定の日には入れない
- 1日の上限時間を超えない。収まらない場合は、内容を減らす案を出す
- AIの呼び出しはサーバー側で行い、APIキーをブラウザに出さない

# 通知
- 計画の確定後に「ホーム画面に追加」と通知許可を案内する。iPhoneではホーム画面に追加しないと通知が届かないことも伝える
- 毎晩21時（Asia/Tokyo）にpg_cronでEdge Functionを実行し、各ユーザーの記録を確認する。崩れていればreplanを作り、遅れを通知する（例：「経済学、2日分の遅れがあります」）
- 翌朝以降は、記録が再開するまで毎朝7時に組み直し後の今日の予定そのものを通知する（例：「今日：経済学 30分（第3章の続き）」）
- 通知をタップすると /replan が開く

# デザイン
- コンセプト：誰でも楽に使いやすく。1画面でやることは1つだけにし、迷わせない
  - 主な操作ボタンは画面下部の親指が届く位置に置く
  - アイコンだけのボタンは使わず、必ず文字ラベルをつける
  - 専門用語を使わない（「リスケジュール」ではなく「組み直し」など）
- 色：黒ベースでクールに、見やすく
  - 背景は黒（#121212前後）、カードは一段明るい黒（#1E1E1E前後）
  - 文字は白（#F2F2F2前後）、補足の文字はグレー（#A0A0A0前後）
  - メインのボタンと強調は青（#4DA3FF前後）
  - 「できた」は緑（#3DDC97前後）、遅れの表示は赤ではなく黄色（#F5B841前後）
  - 文字と背景のコントラストはWCAG AA（4.5:1以上）を満たす
- フォント：大きく見やすく
  - Google FontsのNoto Sans JPを使う
  - 本文は18px、見出しは24px以上、今日のTask名は28px程度
  - 行間は1.7程度
  - ボタンの文字は18px以上の太字
- 幅375pxのスマホを基準に設計し、タブレットとPCでは中央寄せで最大幅を持たせる
- ボタンは指で押しやすい高さ（56px以上）
- 文言はすべて日本語。遅れを責めず、「もう組み直してある」ことを伝える口調

# 仕上げ
- 初回表示ではサンプル計画（経済学の期末試験、毎日30分、期限3週間後）を入れ、「サンプルを消す」ボタンも置く
- READMEにページ構成、ファイル構成、Supabaseのテーブル作成SQL、Edge Functionsのデプロイ方法、pg_cronの設定、環境変数（AIのAPIキー、VAPIDキー、SupabaseのURLとキー）の設定場所を書く
```

## このプロンプトのあとにブラウザ版に足した機能

- 今日の予定を自分で追加できる（1日の目安を超えるときは注意を出す）
- デモ用に日付を1日ずつ進められる
- アプリを開くと、まず昨日の予定をスワイプで「できた／できなかった」と記録し、そのあと今日の予定を表示する
